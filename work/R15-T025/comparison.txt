2. CALLABLE INTERFACE DESIGN AND DELIVERY SEPARATION
----------------------------------------------------
Callable Interface:
  `process_message_stream(inputs, service_adapter=None) -> ProcessingResult`

Adapter Signature:
  `service_adapter(message: Dict[str, Any]) -> ServiceAcknowledgement`

Logical Separation:
  - Validation: Isolates malformed inputs into `rejected` list; does not reserve identity.
  - Deduplication: Isolates repeated (device_id, timestamp) pairs into `duplicates` list.
  - Chronological Sorting: Sorts `accepted` messages prior to downstream submission.
  - Adapter Submission: Only accepted messages are submitted, in strict chronological order.
  - Adapter Return Validation: The pipeline inspects the adapter return value before accessing fields:
      * Requires a `ServiceAcknowledgement` instance.
      * Requires status to be strictly "DELIVERED" or "FAILED".
      * If the adapter returns `None`, a string, an unexpected status (e.g. "PENDING"), or raises an exception,
        the pipeline produces a `ServiceAcknowledgement` with status "FAILED" and descriptive details.
  - Delivery Guard: If the acknowledgement status is != "DELIVERED", the message is routed to
    `failed_deliveries` and NEVER falsely marked in `delivered`.
