2. BASELINE AND REFACTORED ARCHITECTURAL COMPARISON
---------------------------------------------------
Baseline Architecture (Monolithic):
  Function: `classify_record_baseline(record, bounds) -> ClassificationResult`
  Behavior: Combines input extraction, latitude/longitude type validation, range checks,
            and bounding box containment within one large function.

Refactored Architecture (Separation of Concerns):
  Function 1: `validate_coordinate_fields(record) -> (is_valid, lat, lon, reason)`
              Handles field extraction, type enforcement (no booleans, no strings, no non-finite values),
              and geographic bounds [-90, 90] and [-180, 180].
  Function 2 (Extracted Responsibility):
              `is_inside_geofence(latitude, longitude, bounds) -> bool`
              Pure geometric boundary test verifying that latitude and longitude fall within the
              inclusive bounding box.
  Function 3: `classify_record_refactored(record, bounds) -> ClassificationResult`
              Orchestrates validation and boundary testing, returning structured ClassificationResult.
